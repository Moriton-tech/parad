# parad.mn — Морьтон Парад (нэгдсэн вэб)

Нэг сайтад: **парадын тасалбар**, **азарганд гүү тавих захиалга**, **азарга/адуу зарах** (тогтмол үнэ, хүсэлт, дуудлага худалдаа), **адууны каталог**.

- Frontend: статик HTML + ES modules (build хэрэггүй) — GitHub Pages / Vercel / аль ч static hosting
- Backend: Supabase (Postgres + Storage + нэг Edge Function `parade`)
- Хуучин `Burtgel`, `auction` сайтуудыг **өөрчлөөгүй**. Энэ нь шинэ, тусдаа төсөл.

## 1. Supabase төсөл үүсгэх

1. supabase.com дээр шинэ төсөл үүсгэнэ (хуучин Burtgel-ийн төслийг ашиглахгүй).
2. **SQL Editor** дээр дарааллаар ажиллуулна:
   1. `supabase/schema.sql` — тасалбар, захиалга, ажилтан
   2. `supabase/horses.sql` — адуу, гүү тавих, хүсэлт, дуудлага, Storage `horses` bucket
   3. `supabase/seed.sql` — 19 азаргын анхны каталог (дахин ажиллуулахад давхардахгүй)
3. **Authentication → Users** дээр админ хэрэглэгч (имэйл + нууц үг) үүсгээд SQL Editor-т:
   ```sql
   insert into parade_staff (email, role) values ('таны@имэйл', 'admin');
   ```

## 2. Edge Function

```bash
supabase functions deploy parade --no-verify-jwt --project-ref <ref>
```
(Dashboard-оос бол функцийн тохиргоонд **Verify JWT-г унтраана** — админ шалгалтыг функц өөрөө хийдэг.)

Secrets (`supabase secrets set …`):

| Нэр | Тайлбар |
|---|---|
| `QPAY_CLIENT_ID`, `QPAY_CLIENT_SECRET`, `QPAY_INVOICE_CODE` | QPay merchant (хоосон бол дансны шилжүүлгээр) |
| `QPAY_MODE` | `live` эсвэл туршилтад `sandbox` |
| `PUBLIC_FUNCTION_URL` | QPay callback-д хэрэглэх функцийн бүтэн URL |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS` | Gmail SMTP (App password) **эсвэл** |
| `RESEND_API_KEY` | Resend (имэйл илгээх өөр сонголт) |
| `MAIL_FROM` | Илгээгчийн нэр (заавал биш) |

`SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` нь автоматаар орно. Бүх хүснэгтэд RLS нээлттэй эрхгүй — зөвхөн энэ функц service_role-оор хандана.

## 3. Frontend

1. `js/config.js`-д шинэ төслийн утгыг оруулна:
   ```js
   SUPABASE_URL: 'https://xxxx.supabase.co',
   SUPABASE_KEY: '<publishable key>',
   ```
2. Repo-г GitHub-д push → Pages идэвхжүүлнэ (эсвэл Vercel-д холбоно).
3. **parad.mn** домайн DNS-ийг hosting-руу заана (GitHub Pages бол `CNAME` файл + A/CNAME бичлэг).

## 4. Админ хуудсууд

| Хуудас | Зориулалт |
|---|---|
| `admin.html` | Тасалбар, оролт шалгалт, сугалаа, парадын тохиргоо, ажилтан |
| `admin-horses.html` | Адуу бүртгэх/засах/зураг, гүү тавих захиалга, зарах хүсэлт, дуудлага, тохиргоо |

Анхны ажил (дарааллаар):
1. **admin.html → Тохиргоо**: парадын огноо, байршил, тасалбарын үнэ оруулаад «парад зарлагдсан» (`event_public`), хүсвэл `sales_open` асаана. Тэр хүртэл нүүр хуудсанд «Удахгүй» гэж харагдана. (Схемийн анхны огноо зөвхөн placeholder.)
2. **admin-horses.html → Тохиргоо**: данс, лавлах утас, нөхцөл, имэйл.
3. **Адуу**: азарга бүрийг нээж үнэ, суудал (анхдагч 10), зураг, зарах хэлбэрийг тохируулна.
4. Хуучин «гүү тавих» захиалга байвал **Гүү тавих → Хуучин систем импорт** (заавар хуудсан дотор).

## 5. Ажиллах дүрэм

- **Гүү тавих**: захиалагч GT-XXXXXX код авна → админ баталгаажуулна → суудал хасагдаж дараалал (баталгаажсан цагаар) тогтоно. Баталгаажаагүй захиалга 24 цагийн дараа (тохируулж болно) хүчингүй болно. Суудлын хэтрэлтийг DB түвшинд түгжээгээр хамгаална.
- **Үнэ**: азарга бүрд ₮ (хоосон = Private), хямдрал %.
- **Дуудлага**: эхлэх үнэ, алхам, эхлэх/дуусах цаг; сүүлийн минутад бооцоо тавивал цаг автоматаар уртасна (анти-снайпинг). Админ хуурамч бооцоог «хүчингүй» болгож, «Дуудлага хаах»-аар ялагчийг тогтооно.
- **Зарах**: тогтмол үнэ эсвэл «авах хүсэлт» → админ утсаар холбогдож «Зарагдсан» гэж тэмдэглэнэ.

## Анхаарах зүйл

- Дуудлагын бооцоо нэр + утсаар л баталгаажна (OTP байхгүй). Ялагчтай админ утсаар холбогдож баталгаажуулах ёстой.
- Edge function-ыг бодит Supabase дээр ажиллуулж туршаагүй; SQL-ийг локал Postgres дээр, функцийг синтакс/төрлөөр шалгасан. Анх deploy хийсний дараа нэг захиалга, нэг бооцоо, нэг тасалбарыг эцэс хүртэл туршина уу.
- QPay болон имэйлийн түлхүүр оруулах хүртэл төлбөр автоматаар баталгаажихгүй (дансны шилжүүлгийн замаар ажиллана).
